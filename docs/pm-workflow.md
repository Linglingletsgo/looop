# PM 研究与产品目标

实现日期：2026-10-17。入口仍为 looop 项目卡片的执行设置和单次／持续运行。

## 已实现

- 项目自有技能优先；可用 `.agent/project.json` 的 `research.skill_paths` 显式指定路径，否则扫描项目常见技能目录。
- 缺少适用方法时，从 `pm-skills/` 选择默认方法。项目已有技能却要使用默认方法时，PM 必须说明具体缺口。默认方法自动包含 investigation 协议，固定版本和内容摘要会被核验。
- 六项精简适配：自主调研、竞品比较、机会分析、backlog 排序、需求简报、假设检验。完整上游原文和许可证保存在同一目录，运行时只加载选中的精简方法。
- 先选择研究问题和停止条件，再实际研究。方法应用说明、来源引用、摘要和抓取时间随当前研究简报保存。控制器独立读取引用来源并核对原文；引用存在不等于结论正确，研究仍需说明反证和未知。
- 研究结论不支持或证据不足时不生成开发切片。公共来源抓取失败作为证据缺口保存，不把网络失败伪装成产品结论。
- 项目状态只维护最新 `research` 和一个 `product_goal`。后者包含用户价值、成功条件、剩余工作、当前进度和已交付切片数。切片交付不自动完成源需求。
- 单次执行推进一个目标，允许多个切片与 PR；只有全部目标标准有当前代码证据、交付已结束，PM 才能完成目标。仍沿用项目配置的审核、检查和合并策略；没有新增默认 Acceptance 阶段。
- 选题期间的外部决定变化使旧方案失效，绑定和目标完成均核验规划版本。暂停停止新规划，已启动工作按原有规则收尾。
- 看板展示目标与剩余工作、PM 调研结论及方法应用；任务证据包含引用和方法版本。独立对话的自报进度明确标记，不自动当成审核通过。

## 使用方式

1. 在项目卡片的执行设置选择「只推进 Backlog」或「Backlog + 调研新需求」。
2. 点击「单次执行」推进一个目标，或「持续运行」在目标完成后继续下一项。无值得执行的工作则休眠。
3. 从卡片查看当前目标和「PM 调研」，从任务「证据」查看对应研究来源及交付问题。

沿用执行器设置中选定的真实 Codex、OMP 或 Claude Code harness 及已配置订阅；本次未修改路线或模型。Command Code 仍只使用 DeepSeek Flash，不增加付费 API。

只有满足项目原有执行条件的项目才能启动。WOS 自有研究技能和需求批准责任不被默认包覆盖，WOS 自动执行仍未开启，DS1 仍是人工 worktree。未将本次验证变成业务项目需求。

## 不依赖 Paperclip 的使用

项目对话通过 `.agent/tools/project-session.py context --repo .` 读取相同当前状态，通过 start/progress/finish 命令记录独立工作。新适配导出包括 `project-session.py`、`project_state.py` 和 `product_goals.py`；没有 Paperclip 时也能使用这些标准库工具。

需要通用方法时，从 looop checkout 读取相关 `pm-skills/<method>/SKILL.md` 和 `pm-skills/investigation/SKILL.md`，优先遵守项目规则。不要为每个项目再复制一整套提示词。已有旧版项目工具不被本次静默覆盖；在该项目自己的对话中对照版本审核升级即可，旧工具仍可读取共享状态。当前研究与目标不会因打开不同对话而另建一份。

## 验证

- Linux Python suite：235 项通过。
- HTTP integration：通过，包含实际子进程状态写入、鉴权、版本冲突、幂等和暂停等检查。
- 新增覆盖：项目技能优先、默认补缺理由、默认正文及原始版本摘要、证据缺失不派发、需求变更时拒绝旧调研、多切片持续同一目标、切片交付不提前完成需求、暂停保留、独立进度标记。
- 真实 Codex harness：独立临时仓库中，实际加载 investigation 与 backlog-prioritization，使用真实工具读取代码并独立核对三条来源；通过，未创建任务或 PR。
- 独立导出工具：在调度器之外、无 Paperclip 和额外 PYTHONPATH 的临时目录中，初始化、读取状态、start/finish 同步检查通过。
- Linux Chromium：通过已登录服务读取看板，以临时响应展示目标与研究；桌面 1440px／手机 390px、单次执行说明和无 JS 错误检查通过，没有提交看板操作。

测试证明调度协议和当前实现可工作，不代表真实产品需求已得到市场验证。完整无人值守产品研究的质量仍需后续实际运行评估。
