# PM 研究与产品目标

实现日期：2026-10-17。入口仍为 looop 项目卡片的执行设置和单次／持续运行。

## 已实现

- 项目自有技能优先；可用 `.agent/project.json` 的 `research.skill_paths` 显式指定路径，否则扫描项目常见技能目录。
- 缺少适用方法时，从 `pm-skills/` 选择默认方法。项目已有技能却要使用默认方法时，PM 必须说明具体缺口。默认方法自动包含 investigation 协议，固定版本和内容摘要会被核验。
- 六项精简适配：自主调研、竞品比较、机会分析、backlog 排序、需求简报、假设检验。完整上游原文和许可证保存在同一目录，运行时只加载选中的精简方法。
- 先选择研究问题和停止条件，再实际研究。方法应用说明、来源引用、摘要和抓取时间随当前研究简报保存。控制器独立读取引用来源并核对原文；引用存在不等于结论正确，研究仍需说明反证和未知。
- 研究结论不支持或证据不足时不生成开发切片。公共来源抓取失败作为证据缺口保存，不把网络失败伪装成产品结论。
- 项目状态只维护最新 `research` 和一个 `product_goal`。后者包含用户价值、成功条件、剩余工作、当前进度和已交付切片数。切片交付不自动完成源需求。
- 单次执行推进一个目标，允许多个切片与 PR；只有全部目标标准有当前代码证据、交付已结束，PM 才能完成目标。仍沿用项目配置的审核、检查和合并策略；没有新增默认 Acceptance 阶段。
- 选题期间的外部决定变化使旧方案失效，绑定和目标完成均核验规划版本。暂停停止新规划，已启动工作按原有规则收尾。
- 看板展示目标与剩余工作、PM 调研结论及方法应用；任务证据包含引用和方法版本。独立对话的自报进度明确标记，不自动当成审核通过。

## 当前选题与上下文契约

PM 派发必须给出具体问题、可观察收益和当前切片的必要性，并以当前代码与核验来源支持。缺一条测试本身不足以说明产品价值；没有已知失败、具体风险或对当前目标的必要贡献时应返回 no_work。material=false 会转换为无工作并休眠；缺失或错误结构沿用有限格式纠正，不扩权。结构校验不能证明模型的价值判断真实，仍由来源核验、代码审核与实际结果约束。

各阶段使用独立调用。PM 只接收有效决定、当前选中需求、目标摘要和必要调研结论；选中目标后不再夹带其它待办、草稿或交付清单。调研方法目录只传一次；后续决策保留结论、反证、建议和精确引用，版本哈希、许可证、抓取时间及方法选择说明留在审计产物。项目原生规则和适用约束不因精简而删除。

Reviewer 与可选验收接收同一目标 SHA 的控制器检查回执（命令、退出码、最多 2,000 字符输出尾部），独立检查差异并按需补充针对性验证；不共享 Builder 对话，不默认重复整套检查。项目强制检查继续生效。格式纠正提示保留原阶段与权限，不再与 PM 提案阶段冲突。

Linux 验证：257 项 Python 测试与 HTTP 集成通过。独立夹具覆盖规划→审核格式失败→同提交恢复→一次发布→模拟合并→真实 Git 主线刷新与复验，Builder 不重复。另以真实 Codex 只读调用验证重复测试机会返回 no_work，提示词 2,584 字符；这只是该夹具的输入规模，不等于总 token 消耗或所有选题质量保证。未启动 GTP 新任务，仍 paused。

## 输出传输与已完成 Builder 的恢复

阶段结果以每次执行的 handoff.json 为准。Agent 用文件工具写入 JSON，控制器校验后推进状态；聊天总结不参与解析。无效、缺失或含糊结论不能默认通过。

Codex、Claude Code、OMP 使用同一文件交接协议，不要求最终对话为 JSON，也不依赖原生最终响应约束。交接文件与自然语言报告分别保留。

Builder 调用前记录 run_id、工作区和原候选 SHA。输出格式失败后，显式 resume_builder=True 只接收已停止、未发布、同 Packet/policy/基线/候选且文件变化在授权内的已完成工作区；必须能读取明确的 ready 结论。保留原产物并提交候选后，从全量配置检查和独立审核继续，不为纠正格式再次写代码。首次 Builder 失败也支持此恢复；无法判断真实结论时仍停止。新审核发现真实缺陷继续原有修改循环，不能以格式恢复绕过。

## 使用方式

1. 在项目卡片的执行设置选择「只推进 Backlog」或「Backlog + 调研新需求」。
2. 点击「单次执行」推进一个目标，或「持续运行」在目标完成后继续下一项。无值得执行的工作则休眠。
3. 从卡片查看当前目标和「PM 调研」，从任务「证据」查看对应研究来源及交付问题。

沿用执行器设置中选定的真实 Codex、OMP 或 Claude Code harness 及已配置订阅；本次未修改路线或模型。Command Code 仍只使用 DeepSeek Flash，不增加付费 API。

只有满足项目原有执行条件的项目才能启动。WOS 自有研究技能和需求批准责任不被默认包覆盖，WOS 自动执行仍未开启，DS1 仍是人工 worktree。未将本次验证变成业务项目需求。

## 不依赖 Paperclip 的使用

项目对话通过 `.agent/tools/project-session.py context --repo .` 读取相同当前状态，通过 start/progress/finish 命令记录独立工作。新适配导出包括 `project-session.py`、`project_state.py` 和 `product_goals.py`；没有 Paperclip 时也能使用这些标准库工具。

需要通用方法时，从 looop checkout 读取相关 `pm-skills/<method>/SKILL.md` 和 `pm-skills/investigation/SKILL.md`，优先遵守项目规则。不要为每个项目再复制一整套提示词。已有旧版项目工具不被本次静默覆盖；在该项目自己的对话中对照版本审核升级即可，旧工具仍可读取共享状态。当前研究与目标不会因打开不同对话而另建一份。

## 2026-10-18 规划恢复修复

- 所有原生 harness 子进程清除继承的 Git 仓库覆盖变量，并将 Git 向上查找边界设为工作区父目录。无 `.git` 的只读快照不会误读 looop 仓库；有独立 Git 元数据的交付工作区仍可正常使用 Git。快照基线来自控制器，不伪造 Git HEAD。
- 调研规划在提示词首尾明确当前阶段及 JSON 契约。研究问题、停止条件、技能选择和报告格式在只读调用内验证；错误格式最多使用原有三次调用预算纠正，保留每次产物和恢复摘要。每次调用前及验证前核验当前授权，决定变化立即停止。无总运行时限。
- 引用路径必须是现存文件路径，不带 `:行号`。模型可自行纠正路径格式；控制器仍独立验证原文，不将不存在的引用、未匹配的引文或产品结论改写成成功。证据不足或拒绝结论不会触发开发。
- 原生 AGENTS 文件始终完整注入。超过 16,000 字符的其它规则文档保留原文件，提示词提供最多 60 条标题与行号导航，并要求按需读取适用约束；无标题文件仍要求从原文件检索适用约束。索引不替代项目规则。近期交付只注入标题、需求与路径，控制器的完整去重依据不变；不再默认全文读取 HANDOFF。
- 同一 GTP 失败快照的规则上下文由 323,973 字符降至 3,911 字符，未修改业务文档或授权。核实旧失败尝试无存活进程、无交付绑定后，将其关闭为 cancelled，保留原错误、全部证据及修复版本；项目仍为 paused，未自动重启 GTP。
- Linux 验证：241 项 Python 测试及独立 HTTP 集成通过。真实 Codex 在 looop 仓库内的无 Git 临时夹具完成两阶段只读调研，核验 4 条来源，引用路径错误自动纠正一次；最大注入提示词 6,358 字符。未创建业务任务或 PR。

### 同版本失败后的重新启动

只有 queued、no_work、rejected 的规划结果可作为同基线、同规划版本的选题去重记录；cancelled 失败记录保留审计与切片指纹，但不冒充已完成选题。未解决的 blocked 仍由原有门禁拦截，不自动重放。命中有效去重时，同时更新项目 selection，避免页面残留旧的等待文案。新增覆盖完整失败关闭→单次启动→实际规划调用，以及真正无工作结果仍不重复调用模型；Linux 243 项 Python 测试通过。


### 审核输出格式恢复

只读交付角色的交接文件经过 verdict 与 findings 校验，业务 blocked/changes_requested 不会因格式纠正而改写。格式修复前后核验任务门禁、基线及目标提交。审核 run_id 指向实际成功写入文件的执行。

显式 `delivery.execute(..., resume_review=True)` 仅恢复未发布、工作进程已退出的审核格式失败。核验原 Packet/policy、基线、候选提交、干净工作树、授权改动路径及恢复次数后，保留旧 state、Builder、检查与审核产物，从同一提交重跑检查和独立审核，不重跑 Builder。原生任务阻塞不能走此快捷恢复。恢复的新检查产物以 checks-<round>-resume-<n>.json 保存；合并控制器读取对应新产物，不能沿用旧检查。若新审核要求修改，则回到项目原有 Builder 循环。运行没有新增总时限，发布与合并仍受既有配置门禁控制。

Linux 验证：251 项 Python 测试及 HTTP 集成通过，覆盖格式纠正、明确阻塞不重试、同提交恢复且 Builder 不重复、脏候选拒绝、共享状态恢复及新检查证据门禁。

Research format corrections receive the prior bounded response so source evidence is not lost across fresh harness calls. An `insufficient_evidence` report continues the same question with up to two targeted read-only follow-ups; `human_decision` and `wait_source` stop immediately with an explicit planning blocker. A remaining gap is `research_incomplete`, never `no_work`: the owner can resolve it through the planning intervention entry, and the next attempt receives the bounded question and gap for the same baseline and planning revision. Rejected research and a genuine lack of valuable work remain idle outcomes. Source quotations, project guards and independent review are unchanged.

所有调度阶段使用独立的 handoff.json 和 handoff.schema.json。控制器创建 version/run_id/nonce，Agent 只更新 result；文件必须通过严格 JSON、字段结构与执行身份校验。文件可被无 Paperclip 的外部对话读取；项目当前状态仍由控制器校验后同步，避免并发覆盖。Builder 漏写或写坏文件时，仅只读修复交接，不重做开发；自然语言保留在 result.md。产物沿用既有有界保留策略。


### 审核输入

成功检查只注入目标 SHA、命令、退出码及现有检查产物路径；完整输出保留在产物，按需读取，不重复注入终端日志。每轮提供完整基线到目标的 diff 命令和变更文件。复审另外提供同一审核模式上一轮的 SHA、结论、发现及产物路径，以及上一轮到当前目标的修复 diff；验证祖先关系，保留完整独立审核，不以旧结论代替当前审批。不传 Builder 对话。先验证既有发现和修复影响，再覆盖完整改动的相关风险；不为凑发现无限探索。输出要求统一指向 handoff.json，运行不设置新增时限。


### 持续循环

continuous 的 no_work 只结束当前调查，15 分钟后在同一代码版本也会自动重新选题；不会因同版本去重永久休眠。未改变的执行任务仍保留去重，不能重复交付相同 Packet。产品目标完成后继续下一目标；once 和 paused 保持原语义。Backlog-only 仍只从待办选题，Backlog-and-research 可以主动调研新机会；价值、调研、范围与独立审核门禁不变。

PM 获得当前 SHA 的主线检查摘要和同目标已合并切片的证据路径。控制器在当前代码上执行该目标既有检查的并集，包含早期切片配置的隔离集成检查；目标 Packet 内新增但遗漏执行的同目录测试，沿用已有成功回执中的定向测试运行器补跑，不执行 PM 自由文本中的命令。按 SHA 和命令集合缓存成功结果；失败明确受阻，不作为无工作或完成证据。目标验证只保留每项目一份当前结果，日志输出有界。不要求只读 PM 重装依赖或连接数据库。

研究引文不匹配时，独立来源核验保持严格；控制器最多发起两次同问题、同方法的只读证据纠正，要求重读具体来源、保留已有证据并诚实调整结论。持续不匹配明确受阻，不默认支持、不按自由文本放行。每次纠正前后保持项目状态门禁。
