# opportunities

Start from one desired user outcome inside the project's approved direction. Separate the user's problem from a requested feature. Use actual feedback, repository behavior or verified research; label unproven demand.
Compare plausible solution directions only as needed to make the decision. Explain user value, tradeoffs, what already exists and why the chosen solution is preferable to doing nothing. Do not manufacture opportunity scores or force a fixed number of branches.
Define observable success criteria for the overall outcome and coherent implementation slices that advance it. A large outcome can span many PRs; test counts and isolated internal tweaks do not establish user value. Preserve an active goal rather than inventing a new one after each slice.
When an assumption needs validation, propose the cheapest permitted check and its failure criterion. A proposed check is not executed evidence. Return the caller's current-state schema, not a growing tree document.
